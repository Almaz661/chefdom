# Barcode Scanner — Status & Next Steps

## What Doesn't Work (DO NOT USE)

- **Video scanner** (`getUserMedia` + `decodeFromVideoDevice`) — **не работает на iOS Safari**. Не использовать этот подход.

## What Partially Works

- **Photo scanner** (`<input capture>` + `decodeFromImageElement`) — работает, но распознаёт штрих-код плохо (~1 из 5 попыток). Нужно улучшить.

- **Service Worker cache** — источник 90% проблем с «страница не обновляется». Нужно бампать `CACHE_NAME` при каждом деплое автоматически.

## Receipt Parser — Product Master (✅ РЕШЕНО, сессия 22.05.2026)

### Проблема
OCR иногда распознаёт чеки ALDI в **двухблочном формате**: все имена сверху, все цены снизу. Порядок не совпадает → привязка по индексу даёт неправильный результат.

**Пример:**
```
Fijn volkorenbrood
Scharreleieren 12st
Kippenvleugels
...
0,99
3,73
6,89
...
```

**Правильная привязка:**
- Fijn volkorenbrood = 0,99 ✅
- Scharreleieren 12st = 6,89 (не 3,73!)
- Kippenvleugels = 3,73 (не 6,89!)

### Решение: Product Master (PR #33)
**Product Master** — система автоматического обучения, которая запоминает цены товаров из прошлых покупок и использует их для точной привязки.

**Алгоритм:**
1. Загрузка Product Master (все товары с `last_price` из БД)
2. Парсинг чека (имена + цены)
3. Для каждого имени:
   - Ищем товар в Product Master (нечёткое совпадение ILIKE)
   - Если нашли `last_price` → находим **БЛИЖАЙШУЮ** цену из списка
   - Помечаем цену как использованную
   - Если не нашли → fallback по индексу
4. Обновляем `last_price` для всех товаров после парсинга

**Преимущества:**
- ✅ Автоматическое обучение с каждой покупкой
- ✅ Без ручного ввода
- ✅ Fallback для новых товаров
- ✅ Работает для всех форматов чеков

**Изменения:**
- Миграция 010: `last_price`, `avg_price`, `price_updated_at` в `products`
- `matchItemsWithProductMaster()` — алгоритм привязки
- `loadProductMaster()` + `updateProductMasterPrices()` в роутере
- Интеграция в `createFromPhoto` и `reparse`

**Статус:** ✅ PR #33 готов к мёржу
